在開始開發簽章、加密之前，有個功能更重要，需要知道使用者是否插卡，或是需要選擇讀卡機，從[上一篇](https://medium.com/p/3e7913bb7caf)可以知道，網站要能夠使用自然人憑證，需要透過 JavaScript 與本地的 HiPKI Local Server (localhost:61161)溝通。本篇會說明如何檢查使用者是否已經插入自然人憑證到電腦上。

* * *

#### p11Image.bmp 介紹

HiPKI Local Server 提供一個路徑 [http://localhost:61161/p11Image.bmp](http://localhost:61161/p11Image.bmp)，讓開發者可以取得讀卡機、卡片的清單。這時候你可能會好奇，bmp不是圖片嗎？打開該路徑什麼也看到不到。看不到是正常的，因為這裡使用圖像[隱寫術](https://zh.wikipedia.org/zh-tw/%E9%9A%90%E5%86%99%E6%9C%AF)，需要經過特定的演算法，才能將圖片轉為文字，並取得讀卡機與卡片的資訊。

因此，我們需要在前端存取上述路徑，載入圖片，並進行演算，把圖片轉換成 JSON 格式。至於為什麼要做多此一舉的事，怎麼不提供 JSON API 就好，我猜可能是為了解決跨域存取問題，這種作法我也是第一次遇到。在開始講範例程式之前，先解釋一下他的隱寫術機制。

* * *

#### p11Image.bmp 圖像隱寫術機制

p11Image.bmp 是一張高度只有 1px 的圖片，所有資訊都往寬度塞，儲存資料的原理是將文字的 ASCII Code 存在 RGB 中，再把他讀出來，如下圖所示。

![](/images/medium/c7f53109f0e94cb2.png)

分成三個步驟將圖片轉為文字資訊：

**步驟一、讀取每格像素的三原色(RGB)，數字介於0–255**

每格像素是一個顏色，而可以將這個顏色轉為三原色表示法，代表這顏色可以透過紅色、綠色、藍色來混合出來，CSS 中的顏色也是透過此方法，更多資料參考[網頁顏色](https://zh.wikipedia.org/zh-tw/%E7%BD%91%E9%A1%B5%E9%A2%9C%E8%89%B2)說明。

**步驟二、依 BGR 順序將數字排序**

這裡演算法設計是依照 BGR (藍綠紅)順序來排列，將三個數字排成一行。

**步驟三、將數字透過 ASCII 轉為文字，串成字串**

將這些數字每個透過 [ASCII](https://zh.wikipedia.org/wiki/ASCII) 轉為文字，例如 65 是 A、66 是 B，並串成字串，這樣就完成了。從上圖我們拿到 ABCDEFGHI 為結果。

* * *
